## ⚙️ 5. Implementation
 
## 🔹 PM1: Footprinting & Reconnaissance (`networkwalks.com`)
 
### Task 1: WHOIS
 
```bash
whois networkwalks.com
```
 
- Registrar: GoDaddy.com, LLC.
- Created: 06/11/2019; expires: 06/11/2027.
- Name servers: `ns6135.hostgator.com`, `ns6136.hostgator.com` (also `ns29.domaincontrol.com`, `ns30.domaincontrol.com` in the registrar response).
- Owner information hidden by Domains By Proxy, LLC.
### Task 2: WhatWeb
 
```bash
whatweb networkwalks.com
```
 
- Web server: Apache; HTTP redirects (301) to HTTPS, then 200 OK.
- CMS: WordPress 7.1.4; WordPress Download Manager 3.3.76.
- jQuery 3.7.1; Bootstrap 7.1.4 (as reported by WhatWeb).
- IP address: `192.232.216.135` (United States); contact: `info@networkwalks.com`.
> Detected technologies and versions are reconnaissance data; they do not prove, on their own, that a vulnerability exists.
 
### Task 3: NSLOOKUP
 
```bash
nslookup networkwalks.com
nslookup -type=NS networkwalks.com
nslookup -type=A networkwalks.com ns6135.hostgator.com
```
 
- The resolver `10.0.2.3` returned `192.232.216.135` (non-authoritative answer).
- NS records: `ns6135.hostgator.com`, `ns6136.hostgator.com`.
- Direct query to `ns6135.hostgator.com` (`50.87.144.87`) succeeded and returned the same IP.
- Timeouts to `10.0.0.1` on port 53 were displayed, but did not prevent the resolution.
### Task 4: curl (to be completed)
 
```bash
curl -I https://networkwalks.com
```
 
Requests the HTTP headers without downloading the page. Result and screenshot to be added.
 
### Task 5: WAFW00F
 
```bash
wafw00f networkwalks.com
```
 
- WAFW00F v2.2.0 detected a WAF: **ModSecurity (SpiderLabs)** (2 requests).
- This is an indication from the tool, not a full evaluation of the WAF configuration.
### Task 6: DNSRecon (failed)
 
```bash
dnsrecon -d networkwalks.com
dnsrecon -d networkwalks.com --lifetime 10
```
 
- Both runs returned `A timeout error occurred`; increasing the timeout from 3 to 10 seconds did not help.
- Basic DNS resolution works (see NSLOOKUP), so the exact cause of the timeout is not yet confirmed.

## 🔹 PM4: Reconnaissance with theHarvester
 
```bash
theHarvester -d microsoft.com -l 1000 -b baidu
```
 
| Parameter | Meaning |
|---|---|
| `-d` | Target domain |
| `-l` | Limit of results |
| `-b` | Data source |
 
- theHarvester 4.6.0 started correctly, but several `Server disconnected` exceptions appeared.
- Final output: `No IPs found`, `No emails found`, `No hosts found`.
- The syntax is correct; the connections to the Baidu source were interrupted. No result does not mean the domain has no emails or subdomains.
**Connectivity check:**
 
```bash
ping -c 4 www.baidu.com
```
 
- 4 packets sent, 4 received, 0% loss (average about 266 ms); `www.baidu.com` resolves to `www.wshifen.com` (`103.235.46.96`).
- A successful ping does not guarantee that the HTTPS service is reachable or accepts automated requests.
**To be completed:**
 

## 🔹 PM5: Network Scanning with Zenmap
 
Zenmap was already installed on Kali Linux, so no download or setup was needed.
 
### Local IP and subnet
 
```bash
ip a
```
 
- Local IP: `10.0.2.15`; subnet: `10.0.2.0/24`.
### Ping scan
 
Zenmap settings: **Target** `10.0.2.15/24`, **Profile** `Ping scan`.
 
```bash
nmap -sn 10.0.2.15/24
```
 
Result: **3 live hosts** (256 addresses scanned in 13.28 seconds).
 
| IP address | MAC address | Note |
|---|---|---|
| `10.0.2.2` | `52:54:00:12:35:00` | QEMU virtual NIC |
| `10.0.2.3` | `52:54:00:12:35:00` | QEMU virtual NIC |
| `10.0.2.15` | not displayed | Local Kali machine |
 
- Nmap does not show the MAC address of the machine it runs on (use `ip a` to read it).
- The two remote hosts share the same MAC, consistent with the virtual network of the lab environment.
### Topology
 
In Zenmap: **Topology** tab, **Legend**, then **Save Graphic** in PDF format. The topology shows the `localhost` node connected to `10.0.2.2` and `10.0.2.3`. All hosts are green (a ping scan does not scan ports, so no open ports were detected).

## 🧠 7. What I Learned
 
1. **Passive reconnaissance:** collecting registration, DNS and technology information with WHOIS, WhatWeb and NSLOOKUP.
2. **Defensive indicators:** detecting a Web Application Firewall with WAFW00F.
3. **OSINT:** searching public sources for emails and subdomains with theHarvester, and understanding that sources can fail or block automated requests.
4. **Network discovery:** running a ping scan with Zenmap and reading IP addresses, MAC addresses and the topology.
5. **Troubleshooting:** a successful `ping` or `nslookup` does not guarantee that other services (HTTPS, full DNS enumeration) will work.
6. **Interpreting results:** detected versions are leads, not proof of vulnerabilities.
---
 
## 🔐 8. Security and Ethical Considerations
 
- Reconnaissance commands are used only in an **authorized, educational** framework.
- Network scans are limited to the lab virtual network (`10.0.2.0/24`).
- Public data collected by the tools is handled in line with applicable rules.
- No exploitation was performed; only information gathering.
